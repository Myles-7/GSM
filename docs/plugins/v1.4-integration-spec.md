# Selective #420 / #422 Integration Contract

Source: tag `v0.8.5`, commit `245ee3107e8a2ba849ee6e04ffdd920d6e35ecea`.
This is a selective adaptation, not a full merge or a release acceptance claim.

## Renderer Integration

Import `openPluginPage` from `src/plugins/pluginPageSession.ts`.
In RepositoryCard, branch before Worker execution:

```tsx
if (action.opensPage) {
  openPluginPage({
    pluginId: action.pluginId,
    pluginName: action.pluginName,
    pageId: action.opensPage,
    pageTitle: action.title,
    repository,
  });
  return;
}
```

Mount `PluginPageHost` once in App, outside repository cards and menus:

```tsx
<PluginPageHost />
```

Optional `t` (app namespace) and `language` props are accepted. Existing Settings
PluginPageViewer uses the same hardened bridge. `PluginPageModal` uses the local
Modal contract (no upstream-only `closeLabel`). No new locale keys are required:
existing app/plugin confirmation keys are reused; example UI strings are local.

`PluginPageModal` accepts `pluginId`, `pluginName`, `pageId`, `pageTitle`,
required `repository`, `onClose`, `t`, and optional `language`.
There is no open-page DOM event: use `openPluginPage`. The only internal
CustomEvent is `plugin-page:revoke`, with `detail: pluginId`.

README is loaded with the existing GitHub service and AbortSignal, keyed by
account/token/repository. Context is a whitelist, not a spread of Store data.
An asynchronous README update sends init with the same token; each reopened
modal receives a new session. App/card integration was provided by the main worker
and verified in the isolated real App smoke described below.

## Desktop Integration

`getPage(pluginId, pageId)` returns `{ success, url, sessionToken }`.
Preload must preserve the token. Page IPC requests carry
`pluginId/pageId/sessionToken/requestId/method/args`.

Inject the factory from `electron/plugins/pluginHostOperations.js`:

```js
hostOperations: createPluginHostOperations({
  clipboard, nativeImage, ClipboardItem, dialog, fs, path, getWindow: () => mainWindow,
})
```

Production main now injects this adapter. Text writes await Electron completion.
Image writes use legacy `writeImage` when present, otherwise Electron 44
`ClipboardItem` / asynchronous `clipboard.write` with a validated PNG Blob.
Only PNG input is accepted. Before native decoding, validate the PNG signature,
the first 13-byte IHDR chunk and its unsigned dimensions: each side <= 8192,
total pixels <= 32,000,000, and neither side zero. Decoded dimensions and image
validity are checked again; oversized headers never reach nativeImage.

All 17 `plugins:*` IPC handlers use `createPluginIpcRegistrar` from `pluginIpc.js`.
Guard IPC by the trusted main window AND the trusted host document URL.
Production trusts the exact selected local index file (including an actual
fallback), not the shared opaque `file:` origin. Hash routes are allowed;
different files, queries, data/blob documents and hostile HTTPS are denied.
Development trusts only the configured loopback HTTP(S) origin and matching
protocol, without credentials. It never admits blob URLs inheriting that origin.
Deny all subframe/plugin-document calls; no Node or preload bridge in plugin frames.
Register `plugin-page` as a standard, secure, non-CORS-bypassing scheme; keep CSP
from `pluginPage.js`, deny popups and navigation outside the initial page.
At navigation start (not merely load completion), window destruction or host reload,
call `manager.revokePageSessions()`. Revoke the affected plugin at frame navigation;
the renderer reopens a session on document load. If navigation is blocked,
keep revoked until the page is explicitly reopened. The shared production
navigation helper revokes at `did-start-navigation` / `will-frame-navigate`,
blocks IPC from an unloading main document until the new `dom-ready`, and
revokes on crash/destruction. Initial blank iframe loads and hash routes retain
their sessions.

Renderer account changes/close send `page.close`; disable/uninstall revoke in
both renderer and manager. `page.close` is an idempotent control message and may
bypass a saturated request queue so cleanup always works; other methods require
a fresh requestId and the active session. `revokePageSessions(pluginId?)` is
available to the desktop worker. The user authorized this worker's plugin-only
main integration; existing DAV, AGY and HTML Reading registration was preserved.
Preload remains desktop-owned.

`plugin-page:revoke` is an internal renderer CustomEvent with `detail: pluginId`;
pluginClient.disable/uninstall and modal-session close/replacement emit it
synchronously. It is not an open-page handler. Opening uses `openPluginPage`
or `pluginPageSession.open`; both accept the same plain object above.

## Invariants And Tests

- host -> page uses exact `plugin-page://<pluginId>`; page -> host may use `*`.
- Validate event source, event origin, payload origin, plugin/page/token/requestId.
- Normal args: UTF-8 JSON <= 1 MiB. Binary args: UTF-8 JSON/base64 <= 10 MiB,
  not 10 MiB of decoded bytes. Both renderer and Node count bytes.
- Max 8 in-flight page requests, 120 requests per sliding minute. Completed IDs
  cannot be replayed. A 10,000-ID session ceiling bounds replay memory.
- AI follows `usePluginAI` consent wording and `forAgyFeature(config, 'plugin')`;
  its entire confirmation/execution is tracked through pluginClient/page journal,
  with stop/abort and no replay. AI provider changes require a new consent request.
- AI preflight/recheck use separate host request IDs; page ID remains consumed.
- Clipboard requires clipboard:write; saving requires downloads:create AND native
  save dialog. Invalid base64/images/names and canceled dialogs never report a write.
- Snapshot sanitizes and deduplicates by id before measuring retained fields
  (including trusted asset URLs) against 64 MiB; failures are atomic.
- Repo Info Card uses a positive HTML/attribute whitelist before preview/copy/export;
  prompts alone are not a sanitizer.

## Acceptance Boundary

Node/jsdom tests cannot prove Chromium custom-scheme origins or native output.
The opt-in `electron/plugins/nativePageSmoke.cjs` probe verifies origins, CSP,
absence of Node/preload, sanitized exports, PNG rasterization and desktop/mobile
rendering with a fake host/provider. Its userData/sessionData and screenshots are
under this worktree's `output/plugin-native-smoke/`, not the user's profile.
That standalone page probe is not evidence of production App integration.

`electron/plugins/nativePluginIntegrationSmoke.cjs` uses real Chromium IPC,
production preload, manager, guard and lifecycle helpers with substituted
outputs. It proves trusted local admission, actual same-frame hostile HTTPS
rejection, blocked subframe revocation, navigation-start revocation before the
new document commits, unloading-document reauthorization denial, destruction,
native image decode and canceled/expired save rejection.

`electron/p020AppSmoke.cjs` starts the real `electron/main.js` and actual Vite App
at `http://127.0.0.1:5174`, with a new profile under `output/p020-app-smoke/`.
It verifies the actual RepositoryCard menu, modal, sanitized repository + README,
personal AI confirmation (zero provider calls before approval), page journal
completion, copy dispatch, actual fixture PNG write, close/account revocation,
and login/confirmation/plugin/appearance/vector screenshots. The provider is
local and deterministic; all non-fixture networking is blocked. It starts
`--hidden`; Windows capture uses an unfocused window outside the desktop.
The save dialog is substituted with a fixture-only path, not interactively tested.
The historical run-0LSy1l used clipboard adapter spies. The subsequent
run-XMuiMu receipt proves physical clipboard text and 2400x2400 PNG writes,
readback and complete restoration of every original item/type byte.
The fixture trusts only native-read plain/html/rtf/png plus the two exact observed
raw OS MIME names `Chromium internal source RFH token` and
`Chromium internal source URL` under `electron application/osclipboard;format="..."`.
All payloads/hashes stay in memory; only type/capability/result flags are recorded.
Each write/restore checks the previous full snapshot for concurrent changes;
unknown proprietary formats still skip physical writes. A detection failure
does not claim physical acceptance. This fixture trust does not broaden the
production PNG-only image permission. Source fingerprints must match over a run.

`electron/plugins/nativeClipboardProbe.cjs` is read-only. It reports per-type
Blob readability, in-memory ClipboardItem byte retention and repeated-snapshot
stability without logging or persisting contents or content hashes. Its current
probe includes unknown Chromium raw metadata, so no system write/clear or
physical roundtrip acceptance is claimed by that read-only probe. Generic raw OS
ClipboardItem support is used by the separate actual-App fixture for its two
trusted native metadata formats; the complete byte-restore receipt is above.

No live AI, real GitHub writes, production userData, native dialog interaction,
remote vector indexing, backend/AGY execution or packaged installer acceptance
is claimed. Do not stage generated profiles/screenshots into the release.
Older handwritten page messages missing `origin` are deliberately rejected;
their authors must update to the V1.4 message shape. The shipped repo-health-page
has been migrated and has successful origin-bearing search and stale/wrong
response regression coverage.
