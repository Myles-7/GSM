# AGY 多并发与功能级配置交付

## 使用入口

完整退出桌面程序（包括托盘）后重新启动，在「设置 → AI 配置 → AGY CLI」配置全局并发及「功能独立配置」。主进程代码必须重启才能生效，仅刷新页面不够。

全局默认 5、范围 1–5。每个功能可覆盖模型、effort、超时和并发；未覆盖的字段继承全局。显式选择「CLI 默认模型」与继承全局不同。功能测试不会自动切换模型，失败也不禁用其他功能。模型与 effort 不一定任意兼容：实测 `gemini-3.8-flash-high` 与 `low` 冲突，现已映射为可操作的错误提示。

## 已实现

- 主进程统一生成池，所有窗口共享全局和功能限额；控制操作保持串行，本地读取不占生成槽。
- 交互优先，连续三个交互请求后让一个可运行后台请求执行；功能名额用满不阻塞其他功能。
- 运行中保存参数不更换已有任务的模型；新任务使用新配置版本。下调并发自然排空，不中断现有生成。
- 真正限流时并发减半、冷却至少 30 秒；至少 60 秒无新增限流且累计五次成功后逐级恢复。额度不足、鉴权、模型/effort 冲突不当作瞬时限流重试。
- 排队取消、运行取消、账户切换、窗口销毁和退出清理；迟到结果不得写入。共享请求预算保留。
- 摘要与详情按字段及任务代次合并结果，保留用户编辑和独立字段；任务面板显示多项运行状态和调度状态。
- 设备配置迁移、功能覆盖保存、恢复继承、独立测试和测试状态失效；本地配置继续排除云同步，备份仍只保留失活描述。
- 仅新增中英文界面内容；HTTP、Embedding 和翻译不改用 AGY。

## 功能覆盖

| 功能配置 | 实际适配 |
| --- | --- |
| 仓库摘要 | 单项、批量、旧发现页摘要；批量独立项目并行，关闭 AGY 的旧响应时长降并发策略 |
| 仓库详情 | 批量工作池、暂停/停止/失败重试、发现订阅详情补充 |
| 分类整理 | 整个分类草案使用独立参数；跨批补分类依赖前批类别，保持顺序，不盲目并行 |
| Gist 摘要 | 批量并发与独立参数，超时不再被旧固定时限覆盖 |
| Release 摘要 | 独立参数，各请求共享全局池；原入口没有新增批量按钮 |
| 查询扩展 | HyDE 与搜索关键词扩展明确归属 |
| 仓库重排 / Gist 重排 | 分别配置、分别限制 |
| 单仓库问答 | 回答、流式、复核与工具编排使用同一功能参数 |
| 工作台研究 | GitHub/本地/混合研究、预选、事实核验、操作建议、聚合；独立仓库并行，单研究链保持依赖顺序 |
| 发现订阅 | 独立筛选批次并行，AGY 不再被旧串行模型调度器二次限制 |
| 插件 AI | 保留确认机制，使用插件配置及全局生成池 |
| 其他文本调用 | 未归属的通用文本请求使用独立兜底配置 |

MCP 桥接目前不直接发起 AGY 文本生成，未增加虚假的模型配置或改变向量兼容性。
