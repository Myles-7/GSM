# GSM 每日 HTML 阅读与回传方案

日期：2026-09-30。状态：已实现桌面设置、HTML 生成、邮件调度和回传合并；实际邮箱发件与手机打开待配置验收。

## 最终决策

停止 Android APK 开发，从当前源码和构建流程移除移动应用。电脑运行 GSM，通过桌面设置 → 每日 HTML 决定内容，默认北京时间 08:00 生成并通过 Gmail 发送附件。手机只阅读仓库和发现，使用已有 AI 摘要与分析；日报流程不新增自动 AI 请求。

手机可修改已读、感兴趣／忽略、阅读笔记、收藏候选。导出修改文本或 JSON，在桌面先预览再确认合并。分类仍在电脑处理，导入候选不执行 GitHub Star。

## 桌面设置

| 分组 | 可设置内容 |
|---|---|
| 页面与仓库范围 | 标题、仓库／发现开关、分类、仓库数量、默认排序、只看未读、隐藏忽略 |
| 发现频道与历史 | 内置／自定义频道选择、每频道数量、已有自定义期刊回看天数 |
| 内容字段 | AI 摘要、原始描述、标签、分类、语言、Star、更新时间、笔记、推荐理由、真实版本说明、来源及分析时间 |
| 分析栏目 | 问题、功能、场景、架构、快速开始、部署、成本、维护，可独立开关 |
| 阅读样式 | 摘要长度、默认页面、主题、字号、密度、附件体积上限 |
| 手机操作 | 已读、兴趣、笔记、收藏候选，各自可禁用 |
| 邮件与调度 | Gmail 本机加密授权、收件地址、连接测试、时间、发送前更新、等待已有更新、立即发送、执行记录 |
| 回传导入 | 粘贴／选文件、差异预览、冲突选择、去重、阅读记录及候选确认 |

关闭的内容从文件载荷排除。缺失分析栏目不占位，不显示原始 JSON。预览与导出使用当前表单；每日任务使用已保存设置。笔记默认不随邮件发送。

## 更新与发送

Electron 主进程触发当天任务，桌面渲染进程读取实际 Store、发现 IndexedDB 与已缓存分析。内置频道每项最多等待 30 秒，总共最多 90 秒；失败保留当前会话缓存和真实更新时间。可等待正在执行的自定义发现任务最多 60 秒，不启动任何新 AI 任务。生成有主进程截止时间，超时记录失败。

08:00 是开始更新时间，不能保证收件箱恰好在 08:00 收到。GSM 必须运行，电脑不能持续休眠；恢复后只检查当天任务。每天每账户最多一次自动尝试，失败／中断留记录供手动处理。SMTP 回执不确定时不会自动重发，先查收件箱。

## HTML 与回传可靠性

单文件内置内容、样式和必要脚本，不请求服务器或模型。来源通过外链打开；不内置完整 README、图片、密钥或桌面本地目录。搜索和分类适用于文件中的内容，列表每次显示 40 条；已打包的内容可以在脚本受限时直接阅读。

尝试按原文件保存手机修改，但本地 HTML 的浏览器存储并不可靠。关闭前导出修改；复制失败可手动选择文本或下载 JSON。原文件可以载入自己的回传包，不能把旧包直接套入新日期快照。

每项操作携带唯一 ID、账户、原快照、项目数字 ID、字段基础值和新值。桌面核对真实导出记录与允许操作，同字段冲突保留双方待选择；应用时再次检查预览后的变化。合并和去重回执同一 IndexedDB 事务落盘，不覆盖分类或 AI 分析。收藏候选需另行确认，并核对 GitHub 项目 ID，才执行 Star。

这些是手动回传，不是实时同步。尚未导回电脑的阅读状态不会出现在次日文件中。
