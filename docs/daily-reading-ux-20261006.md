# 每日阅读：统一项目浏览与批量处理

日期：2026-10-06（北京时间）。本轮按已确认的访谈决策实施，重点是导入后面对大量项目的浏览和处理，导入步骤及设置简化为辅助。

## 使用入口与更新方式

主导航新增 **每日阅读**，内含 **处理项目／导入手机记录／生成与发送／阅读设置**。旧的“设置 → 每日 HTML”保留，默认采用常用设置与折叠的高级设置。

根目录原有快捷方式加载 `dist` 与 `electron`。生产构建更新后，从系统托盘完全退出 GSM，再通过原来的 `GSM-桌面端.lnk` 打开。关闭窗口可能仍保留旧进程；不需要重新安装 APK、更换数据目录或重新配置邮箱。本轮不主动结束用户的真实 GSM，不运行真实 GitHub 写入或发送邮件。

可选桌面目录包位于 `output/daily-reading-ux-20261006/GSM-desktop-final`，使用 `启动GSM.cmd`。它是免安装目录包，根目录快捷方式已能使用新版时不需要解压或覆盖此包。同一时刻只使用一个版本。

## 处理项目：日常主要工作区

- 左侧紧凑列表集中显示名称、用途摘要、收藏状态、兴趣、候选与已保存笔记预览；点击项目在右侧阅读完整摘要、有效分析和笔记。勾选与阅读独立，不因查看详情自动选择项目。
- 导入完成后进入本次导入范围；随时切换全部待处理、全部候选、已处理。没有有效历史导入时默认显示全部待处理。
- 搜索项目名称与已保存笔记，可按阅读、兴趣、笔记及已知 Star 状态筛选。未知状态明确标为“Star 未核实”，没有数据时不假设未收藏。
- 每页 40 项；默认不勾选。“选择全部 N 个匹配项目”只增加当前筛选结果，跨页、跨筛选保留已选项目。显示总选中数量与本页之外的数量，改变筛选不会自动新增选择。
- 批量操作支持已读／未读、感兴趣／忽略／清除兴趣、加入／移出候选、标记已处理／恢复待处理、直接 Star。笔记仍逐项编辑，分类继续在仓库页管理。
- 已处理项目从日常列表隐藏，另在已处理范围查看。忽略的实际变化自动完成；Star 只有在核实成功并完成本地资料持久保存后才完成。恢复待处理后旧的忽略值不会让它再消失。
- 真正新增或修改笔记、兴趣或候选会重新进入待处理；重复回传、同值、单纯已读及位置变化不会反复重开。导入实际改为忽略时仍按忽略完成。
- 已处理后尽量选择附近项目，保持列表滚动。查询、范围、页码、焦点、滚动与草稿按稳定账户 ID 保存在会话内，不跨账户共享。退出整个应用前请保存笔记；存储失效时会提示。

收藏状态展示已有桌面资料或最近成功核实结果。可核实当前页、已选项目或单个详情；核实只读取 GitHub，不执行 Star。核实时间只在实际成功时记录，部分失败不会把其他项目假设成未收藏。

## 笔记与并发保护

编辑时保存原始笔记基线。切换项目或进入导入界面保留草稿；写入失败保留文本。导入期间出现新笔记时，显示当前已保存内容，暂时禁用保存，明确选择“使用当前笔记”或“保留草稿并确认覆盖”。不会把旧草稿直接套用新项目版本。

确认保留草稿后还需点击保存；保存事务再次检查当时的项目指纹。保存期间继续输入，新的输入以本次成功保存值作为基线保留，不会被清空，也不会误报与自身保存冲突。

## 直接批量 Star 与恢复

已选项目不必先加入候选。点击 Star 后显示当前账户和完整项目清单（每页 40 项），确认一次才执行；取消不发写请求。

复用已有持久批次：核实 Token 所属数字账户 ID、仓库数字 ID、规范名称和实际 Star 状态，再串行执行。原本已收藏会补齐本地资料后跳过 PUT。连续写请求间隔至少一秒，认证、权限和限流暂停，普通单项失败继续。

GitHub 成功、本地保存失败、同步失败分别显示。响应丢失先核实；停止不发后续写请求，不撤销已完成的 Star；账户或凭据变化停止执行。重开 GSM 后需确认剩余项目，不自动继续。新笔记或导入导致指纹变化时，迟到的 Star 结果不能清除新候选或隐藏新待处理变化。

## 导入与设置

导入采用选择记录 → 核对变化 → 处理项目。第一步选择文件或粘贴后才展开输入。预览首先给摘要与待处理冲突，普通修改按项目归组折叠。原 v1／v2 JSON、文件数量与体积限制、账户／快照校验、笔记逐项冲突及事务重检保持兼容。JSON 导入不会自动 Star。

常用设置只显示阅读预设、仓库范围与数量、发现频道、字号与间距、邮箱状态和发送时间。栏目、顺序、历史、缓存与文件限制仍在高级设置，已有覆盖继续有效。切换预设对覆盖配置的处理保留现有明确确认规则。

“生成与发送”使用已保存配置；设置中的预览与手动导出使用当前表单。原定时 Gmail、未确认发送保护、附件保存和补发流程保持。

## 数据迁移与范围边界

严格的手机 ReadingState 及 v1／v2 回传字段未更改。桌面处理信息在阅读账户中独立保存：项目来源、处理状态、Star 观测、版本与最近有效导入。候选来源与 Star 批次沿用独立存储。

首次升级旧账户时，在 IndexedDB `gsm-html-reading` 的 `migration-backups` 保存 `<账户 ID>:before-workspace-v5`，备份与迁移同事务；失败保持旧资料，现有备份不覆盖。旧忽略状态一次回填为已处理，后续明确恢复保持生效。旧候选没有来源时不编造时间。

这是一致性迁移保护，不替代磁盘备份。测试用隔离账户验证，没有迁移真实运行账户。若整体回退程序，先退出 GSM，再恢复升级前完整用户数据目录，不让旧程序写入新结构。

回传 JSON 不是完整仓库或分析数据库。统一详情使用当前账户有效分析资产及已有公开描述，遵守分析删除标记；历史资料不存在时不伪造，也不自动调用模型补齐。
