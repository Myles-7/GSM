# 个人仓库治理

个人仓库：Myles-7/GSM。官方上游：AmintaCCCP/GithubStarsManager。

## 分支与版本

- `personal/main`：个人版默认分支，经过质量检查的交付基线。
- `codex/*`：开发分支，通过 PR 向 `personal/main` 集成；PR 描述注明实际验证范围。
- 原 `main`：保留的历史上游参考分支，不代表当前个人交付，也不自动同步或合并上游。
- 应用 package 与完整上游基线保持 v0.8.4；P0.2.1 是已有桌面维护交付。
  后续功能集成以提交和交付记录标识，不冒称完整升级 v0.8.5。
- 个人版支持简体中文与英语。其余语言资源留作上游参考，历史语言定义仅用于 API 兼容。

## 检查与发布

CI 对个人默认分支、`codex/*` 推送及 PR 执行前端/Electron 测试、lint、类型、
中英翻译、分层、插件和构建检查；独立服务端 job 执行测试和构建。
PR 还检查新硬编码文案与版本文件。检查失败不得把该提交描述成已验收交付。
自 2026-10-04 起 lint 为 `eslint . --max-warnings 0`：错误和警告均必须为零。
保护默认分支：要求 PR、Quality gates 与 Server quality gates 成功、解决讨论，
禁止删除和非快进推送；个人维护无需另一个人的强制审批。
强制检查启用严格分支同步，管理员同样受保护；使用 merge commit 保留模块提交历史。

上游安装包和更新 feed 不代表个人版可直接覆盖。Git 推送不发布安装包、部署服务，
也不备份运行数据。已有发布工作流保留，不在个人分支普通推送时发布桌面或 Docker。
个人仓库停用继承的桌面/Docker 发布工作流；个人发行方案验收后再明确启用。
前端 CI 使用 Node 24，服务端原生测试使用 Node 22；Linux/Node 24 下旧版 SQLite
模块的清理崩溃需在独立依赖升级中解决，不能将 Node 22 验证冒称为 Node 24 服务端验收。

## 提交卫生与恢复

- 源码、相关测试和维护文档一起保存；共享存储与任务接口的改动按依赖整体集成。
- 不提交 `output/`、`.research/`、临时截图、构建文件、本机后端部署、数据库、密钥或真实账号输出。
- 推送前检查暂存差异和敏感信息，使用普通 push；远端不一致时先 fetch 并查明原因。
- Git 源码恢复点与账号/数据库备份分别管理。数据迁移不能仅靠撤销代码恢复。
- Issue 可记录个人待办，但安全问题和凭据不得放进公开 Issue。
