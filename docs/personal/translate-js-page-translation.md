# translate.js 全页面翻译

日期：2026-09-27

## 决策

- 按用户要求删除旧翻译功能，改用固定版本 `i18n-jsautotranslate@4.0.0`。
- 不是只翻译卡片：在 `App` 生命周期中监听 `document.body`，覆盖导航、列表、详情、README、设置、提示及 Portal 弹窗中的英文文本。
- 顶栏、登录页和 README 工具栏使用同一个全局翻译控制，只有中文显示和原文显示两种状态，不再提供旧的双语模式。
- 保留界面语言设置和 AI 分析；不修改 Electron 主进程、IPC、代理或后端数据。

## 实现边界

- `pageTranslationClient.ts` 懒加载本地打包的 translate.js，调用其 `request.translateText` 和 `client.edge` 服务，不加载远程脚本。
- `pageTranslation.ts` 负责 DOM 观察、恢复、去重、批处理和状态；组件通过 hook 访问，不直接调用服务。
- 仅修改文本节点和 `title`、`aria-label`、`alt`、`placeholder`，不替换元素、不写 `innerHTML`，不修改仓库记录。
- 新 DOM 和 React 更新的文本会重新检查；切回原文只恢复仍与本次译文一致的节点，不覆盖业务更新。过期请求结果不会写回页面。
- 同时最多两个批次，每次请求最多 40 段、6000 字符；超长段落拆分并按原节点合并。缓存仅保存在内存中，最多 2000 个原文条目。
- 失败保留原文，显示重试入口，不无限自动重试。
- 新偏好 `pageTranslationEnabled` 在现有 Zustand 持久化结构中保存，初始关闭。旧引擎和卡片开关不迁移成默认整页翻译，以免扩大内容发送范围。

## 隐私与限制

- 开启后，符合条件的页面文本会发送到 Microsoft Edge 在线翻译端点，包括页面上展示的自定义描述或聊天内容。这不是离线翻译。
- 不读取或发送输入框的值、编辑器内容；跳过代码、命令、数学公式、图表、显式敏感区域、URL、邮箱和常见令牌格式。
- 业务组件可用 `translate="no"` 或 `data-sensitive` 标记其他不应翻译的区域。自动检测不能识别所有任意格式的秘密，不应在普通段落中展示未标记的密钥。
- 禁用 translate.js 的持久化文本缓存、内置语言选择器以及默认第三方节点测速和初始化请求。
- 图片中的文字、canvas、跨域 iframe、Electron 原生菜单和系统对话框不属于可翻译 DOM 范围。
- 机器翻译可能保留专有名词，也可能误译技术术语。登录页 GitHub 权限标识 `repo`、`user`、`gist` 明确保留。
- 依然依赖在线服务，速度、可用性和翻译质量没有保证；不宣称比原 Microsoft 通道更快。
- 上游 translate.js 包含未被本集成使用的 `eval` 功能，因此 Vite 构建有依赖警告；未放宽 CSP 或 Electron 安全配置。

## 移除内容

- 旧 Microsoft、Google、AI 翻译服务及相关测试。
- 卡片独立翻译 hook 和开关。
- README 双语渲染组件、专用扫描/分段工具及旧工具栏。
- AI 配置中的翻译引擎设置、`AIService.translateTexts` 和对应提示词快照。
- 旧状态类型、持久化字段和多语言文案；历史字段仅在加载时丢弃。

## 验证

- 单元测试覆盖全页文本、动态弹窗、属性、原文恢复、迟到响应、文本更新、敏感区域、去重、缓存、长文本、并发限制、错误重试和偏好兼容。
- Playwright 使用独立浏览器配置与虚构仓库数据，实测在线翻译、恢复原文和页面切换，并检查桌面/移动视口截图；不修改用户桌面客户端的数据。
- 完整 Vitest 测试需在此机器上通过 `NODE_OPTIONS=--no-experimental-webstorage` 运行，避免当前 Node 原生 localStorage 与 jsdom 冲突。未为此改动业务代码或测试环境。
- 没有重打包安装程序；Electron 独立窗口未进行自动化回归。开发窗口使用已有 Vite 服务。
