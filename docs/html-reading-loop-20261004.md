# 每日 HTML 完整阅读闭环 · 2026-10-04

本轮完善桌面准备、Gmail 附件送达、离线阅读和桌面回传。继续使用桌面已有分析，不增加自动 AI 请求，不开发 APK，回传候选不自动 Star。

## 使用入口

在“设置 → 每日 HTML”查看概览，再按需要调整内容范围、频道配置、阅读样式、邮件发送、阅读记录、存储与清理。

- **保存设置**决定定时邮件使用的配置。普通预览与导出使用当前表单；表单修改后，旧内容检查显示“配置已变更”。
- **预览 HTML**优先使用有效缓存；**更新频道并预览／导出**在请求预算内主动获取新内容。无须先进入发现页面点击各频道。
- 每个频道报告来源状态、资料时间、目标／获取／导出数量与源资料是否已有摘要或分析。设置为“不导出”的内容不会被误报为“未分析”。
- Electron 预览是独立窗口，原生菜单提供五档内容宽度与明暗切换。预览不登记正式回传快照，不改变每日比较基准。浏览器环境使用独立沙箱预览页，存储与剪贴板能力可能受浏览器限制；可下载实际预览 HTML 检查展示。

## 内容可靠性

普通频道的成功缓存按 GitHub 账户、频道和实际查询条件分开保存。默认最多使用 7 天内成功缓存；缓存容量总上限 100 MiB，按最近使用淘汰。失败不会把成功时间改成当天，部分新数据和保留数据分别记录来源时间。

真实成功查询的空结果会清除此前结果，不能用旧列表伪装查询成功。来源失败保留仍有效的内容，并在生成文件中标注缺失或不足；全空可预览诊断，但不能发送。自定义频道只读取已有期刊或有限等待正在运行的桌面生成任务。

预览、导出、手动发送和定时发送共用准备入口。取消、账户变化及迟到响应不能继续提交生成结果。超过文件上限会停止发送，记录失败及频道／栏目体积估算，不截断摘要、不静默删项目。

## 送达与失败处理

默认北京时间 08:00 开始准备；GSM 必须保持运行。当天恢复运行后补做一次，不追补以前多天。账户与日期的持久执行记录防止重复触发自动发送。

| 状态 | 应对方式 |
|---|---|
| 明确尚未提交邮件的暂时失败 | 按已保存策略在首次失败后第 5、15 分钟最多重试两次；重启恢复安排 |
| 认证／配置／超限／全空／用户取消 | 调整问题，再重新生成；不自动重试 |
| 提交后超时或响应丢失 | 标记“发送结果未确认”；不自动重发，先检查收件箱 |
| 附件已保存但发送失败 | 选择重新生成，或直接补发保存附件 |
| 旧日报准备或验证跨到次日 | 在 SMTP 提交前停止；等待当天日报 |

“Gmail 已接受”表示 SMTP 收件地址被接受，不能据此保证手机收件箱已显示或附件可打开。只有这个状态会更新新增／分析更新比较基准；预览、失败和不确定发送都不会更新基准。

自动保存附件默认保留 90 天；最新成功附件、待重试和结果未确认附件保留。清理只处理应用管理目录中自身记录的文件，不清理下载目录。删除附件时丢弃不再用于补发的旧比较索引，保留送达记录和独立的最新基准。

## 手机阅读与回传

顶部和底部导航保持固定且紧凑，使用实际高度和安全区域计算留白。完整摘要不截行；详情目录只列出有内容的栏目，跳转会展开折叠内容。阅读视图增加“本期新增”，仍默认全部和当天排序。

笔记显示本地保存反馈，失焦、导出及页面退出前保存；本地存储失败明确提示立即导出。不同日报文件的手机记录独立，不能指望昨天的文件自动更新今天的文件。

导出显示复制／下载请求时间及之后是否仍有修改，不声称已经回传电脑。记录不会因导出而清空，重复导出允许；重复导入由桌面去重。

桌面“阅读记录”保留粘贴入口，并支持批量文件：一次最多 20 份，单份最多 4,000,000 字节，总计最多 20 MiB。移除无效文件后必须重新预览。对同一字段的不同笔记或状态明确选择，不拼接笔记，不用手机时间判断胜负；位置按快照序号和修订处理，同级冲突展示双方位置。

确认时重新核对电脑当前内容，变化后要求重新预览；业务修改、位置及回执在同一 IndexedDB 事务中提交。保留 v1/v2 协议，旧文件仍可回传。候选数量与确认 Star 分开，导入不会调用 GitHub 写操作。

## 迁移与恢复

阅读数据库 `gsm-html-reading` 升级到 IndexedDB 第 3 版，将不可变快照和发现缓存拆到独立对象仓库，日常配置／状态读取不加载全部历史快照。旧资料迁移先在同一事务保存 `migration-backups` 中的 `账户:before-artifacts-v3`，失败回滚；更早的 v2 迁移备份也保留。

首次升级送达文件会保留 Windows 用户数据目录 `html-reading/delivery-before-loop.json`。送达记录无法解析时保留原文件并停止初始化，不能默默创建空记录后重新发送。Gmail 加密授权文件 `gmail.enc` 不进入 HTML、业务缓存或目录包。

实际升级前仍建议使用桌面资料导出备份。程序处于旧版本运行状态时应从托盘完全退出，再启动新构建；关闭主窗口未必退出。不要用旧程序覆盖写入升级后的阅读数据库。若需恢复旧程序，应恢复匹配的升级前资料，而不是仅替换数据库某个对象仓库。

附件过期清理不删除旧快照的回传校验元数据、阅读记录或去重回执。浏览器自行清除站点数据会影响 IndexedDB 与手机本地记录，不能由附件保留策略防止。
