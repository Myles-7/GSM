# 每日 HTML 回传与批量 Star：交付及验收记录

日期：2026-10-06（北京时间）。

本轮完成桌面端“导入回传 → 收藏候选 → 阅读记录”的处理流程。手机现有 v1／v2 JSON 继续兼容，不需要重新导出。JSON 是阅读修改记录，不含桌面完整项目数据库；导入不会自动执行 GitHub Star。

## 使用新版

已核实根目录内 `GSM-桌面端.lnk` 指向 `D:\桌面\GSM\scripts\start-desktop.vbs`，由现有启动器加载根目录 `dist` 和 `electron`。本轮已更新这两处生产构建，无需另装应用、修改快捷方式或更换数据目录。

从托盘菜单完全退出旧 GSM，再用原快捷方式打开。只关闭窗口可能仍保留旧进程，继续使用旧页面。本轮没有主动结束正在运行的真实 GSM，没有修改 Windows 后端服务、邮箱设置或真实账户资料。

另提供可选的免安装目录包：

- `output/html-reading-return-20261006/GSM-回传与批量Star桌面构建-20261006.zip`
- 解压后的目录：`GSM-desktop-final`，其中 `启动GSM.cmd` 为入口。
- 这不是安装器，不需要将里面的运行时覆盖到原应用。使用当前相同 Electron 应用身份的数据目录；不同应用名称或浏览器来源不会自动迁移资料。
- 原启动方式已经加载新构建时，无需使用这个 ZIP。不要同时运行两个版本。

界面入口：**设置 → 每日 HTML → 回传与记录**，内部分为导入回传、Star 候选、阅读记录三个页签。

## 导入回传

保留粘贴和多文件入口。每次最多 20 份、单份最多 4,000,000 字节、合计最多 20 MiB；继续核对账户、不可变快照、字段格式、操作 ID 和允许的操作。错误文件需移除并重新预览，不能部分绕过校验。

预览显示项目、实际字段变化、候选、冲突和阅读位置数量，重复、无变化与过期位置收进可展开区域。状态冲突可批量保留电脑；手机值唯一时可批量采用手机。笔记、多个不同手机值和不能确定的阅读位置仍逐项选择。

确认时重新检查预览依赖的桌面值，变化后拒绝旧预览。在同一事务中提交阅读修改、位置、回执及候选来源。接受但没有实际改值的操作记作无变化；重复导入不重复增加候选。完成后可直接进入“本次导入”的候选列表。

## 收藏候选与批量操作

候选默认全部待处理、默认不勾选。提供名称／笔记搜索、全部待处理、本次导入、有笔记、感兴趣筛选。每页 40 项，超过 100 条也全部可访问。

“选择全部”只增加当前筛选结果；跨分页、跨筛选保留已有选择。显示总选中数和当前页外选中数，改变筛选不会自动新增选择。

候选显示已有用途摘要、兴趣、来源、笔记预览和执行结果，完整分析按需展开。读取当前账户的有效分析资产与兼容旧分析，遵守删除标记；无可用资料时明确说明。没有新增 AI 请求。旧候选无来源信息时标为历史候选，不编造导入日期。

Star 和批量移除均先展示完整项目清单，按 40 项分页审阅，并显示 GitHub 账户。确认绑定当时的候选来源指纹；来源改变、项目消失或更名时，旧确认失效。真正执行／移除时在事务中再次核对全部选择，避免旧确认处理新的候选版本。

批量移除仅清除候选标记，保留笔记、兴趣、已读、分析和人工资料。失败保留选择。

## GitHub 执行与恢复

执行前使用当前凭据读取 GitHub 用户，核实数字用户 ID 与工作区一致，并再次检查账户／Token 是否变化。随后校验仓库数字 ID、真实仓库名称和实际 Star 状态。仓库改名／转移但数字 ID 不变时使用核实后的名称；名称指向不同数字 ID 时拒绝写入。

批次先持久保存再执行，同一账户只允许一个活动执行。每项串行读取和写入；连续 Star 写请求至少间隔 1 秒，失败／重启恢复仍保留上次写请求时间。限流、认证、权限错误暂停；普通单项失败继续。

实现依据为 GitHub 官方 REST API 最佳实践：串行请求、变更请求间隔至少 1 秒，并遵守服务端限流等待时间。本轮已核对该官方文档。

| 状态 | 含义与后续处理 |
|---|---|
| 待处理／检查 GitHub | 尚未确认本项外部写入 |
| 正在 Star | 请求阶段已持久记录；中断后不能假设失败 |
| 已 Star | 本批次成功写入，且本地仓库资料已持久保存 |
| 已收藏 | 核实原本已 Star，跳过 PUT，补齐本地资料后完成 |
| 失败 | 显示原因；可确认重试剩余项目 |
| 待核实 | 响应丢失／不确定；恢复先查询 GitHub，已成功就不重复 PUT |
| 待完成本地更新 | GitHub 已接受或已核实成功，但本地保存未完成；恢复补齐资料 |
| 未执行／已跳过 | 停止、候选变更等原因未执行本项写入 |

Star 成功后先补齐桌面仓库资料，再等待应用持久存储及已启用的本地 HomeSync 仓库写入；最后事务内完成候选与批次结果。已存在的仓库保留人工字段与分析，不以 GitHub 返回值全量覆盖。

后台同步在批次汇总后触发。同步失败单独显示，可独立重试；不把已成功 Star 重新判成失败。

停止后不发起新的 Star；正在执行的结果仍需核实，已经成功的 Star 不撤销，不执行 Unstar。账户或 Token 改变立即停止新请求，旧账户结果不写入新账户。

退出／重启后不自动继续。点击“检查剩余项目并继续／重试”重新确认剩余清单；成功项目不参与重试。上次持久记录仍是执行中时保留恢复入口，启动新的已确认批次会将旧中断批次暂停。

## 阅读记录

提供全部、已读、未读、感兴趣、忽略、有笔记筛选及名称／笔记搜索，每页 40 项。保留单项阅读操作，不增加批量阅读状态修改。

笔记默认折叠，展开后编辑并明确保存；保存期间锁定该输入及重复提交，失败保留草稿和提示。页签切换保留筛选、分页和未保存输入。

## 迁移与回滚

阅读 IndexedDB `gsm-html-reading` 升级至 v4。账户隔离的 `candidate-sources`、`star-batches` 与旧账户、快照、回执、缓存分开保存，不保存 Token。

首次升级账户时，将原始账户存入 `migration-backups` 的 `<账户 ID>:before-candidates-v4`。备份与账户迁移同事务提交；失败回滚，已存在的该备份不会被后续恢复旧资料覆盖。原始快照校验资料与 v1／v2 回执继续可用。

内部一致性备份用于迁移保护，不替代磁盘故障备份。首次使用新版本前，应在原应用备份实际资料；本轮测试没有升级真实运行账户。需要整体回退旧程序时，先完全退出 GSM，再恢复升级前完整用户数据目录，不让旧程序直接写入新的阅读结构。

- 数据、执行与 UI 分别通过规格／质量审查。修正了恢复查询丢失待核实状态、GitHub 成功后本地落盘保护、候选旧确认、保存中笔记草稿丢失、文件预览切换粘贴沿用旧冲突等问题。

实际 Chromium 中运行现有组件和真实 hook，使用 **5,000 条阅读记录**验证每页 40 项、全筛选跨页选择、确认清单分页、取消不发送 Star、移除保留字段、笔记保存与重开、页签搜索恢复、粘贴导入和来源筛选。无页面异常。

该开发环境测得首屏耗时 8,363 ms（包含动态模块加载、旧新界面装载与 5,000 项分析初始化），单项搜索 216 ms。这不是生产环境启动性能承诺；浏览器开发验证不能证明真实账户同步或 GitHub 网络耗时。

实际目录包使用独立空用户目录启动，验证生产页面加载及邮件／预览 API 可用，阻止网络请求；没有复用正在运行的真实 GSM。其 1,148 个文件在 ZIP 内与构建清单的 SHA-256 全部一致。

待实际账户验收：真实 GitHub 一次确认多个项目、实际权限／网络／限流、真实资料首次迁移和不同 Windows 环境恢复。本轮模拟测试不能替代这些结论；不报告为已完成真实 Star 验收。
