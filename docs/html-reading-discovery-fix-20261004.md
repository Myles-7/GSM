# 每日 HTML 发现频道为空的修复与后续优化

日期：2026-10-04。范围：桌面生成器、设置、定时生成链路；不开发 APK，不部署后端，不新增 AI 请求。

## 原因与判断

用户观察有代码依据。此前手动预览和导出直接读取 `discoveryRepos`，只有邮件发送才调用准备函数。桌面发现按入口懒加载，因此未打开的频道可能没有内存缓存。另一部分已保存资料位于账户及来源条件隔离的发现浏览库中，旧生成器也没有读取它。

“空”并不总是这个错误：自定义频道可能尚无期刊、已有期刊超出回看天数，或项目被未读、忽略及频道展示规则过滤。没有缓存且上游不可用时，程序无法创造真实项目。

## 本轮实施

1. 预览、手动导出、立即发送和每日调度统一通过 `generatePreparedReadingSnapshot`。生成前准备所选频道，随后冻结用于文件的内容。
2. 普通预览与导出优先使用已加载资料；没有资料时读取同账户、同来源条件的浏览库及缓冲项目，再补取普通频道。主题未选择时，与桌面一致使用周趋势；仓库搜索没有查询词则明确提示。
3. 准备结果单独传入快照生成器，不切换频道，不重排或覆盖桌面正在浏览的列表。模型选择、人工资料和阅读记录保持原有规则。
4. 独立准备结果按账户、来源条件、目标数量短期复用 5 分钟，最多 30 份。它是内存缓存，不承诺重启后继续存在。主动刷新失败可回退到同一轮此前成功的导出资料。
5. 新增“更新频道并预览”。普通预览复用已有缓存；此按钮主动更新。发送仍遵守“发送前更新”设置，关闭时优先缓存并补取未加载频道。
6. 普通频道请求沿用总计 90 秒、每频道最多 30 秒、总计最多 20 次分页请求的预算；不足或失败保留可用内容，显示实际数量。自定义频道不自动启动生成；等待已有期刊任务仍最多 60 秒。
7. 设置新增准备进度与“本次内容检查”。频道和期刊逐项显示目标、可用、导出数量及提示。HTML 对应频道分别显示上游查询为空、更新失败、过滤后为空、旧缓存及期刊日期范围等原因，不将这些情况统一伪装成空列表。
8. 保留完整摘要、内容字段与数量自定义、明暗主题、手机操作和 v1/v2 回传。附件超限仍停止发送，不静默裁剪。

## 使用

重新启动加载本项目最新生产构建的桌面 GSM，进入“设置 → 每日 HTML”。选择频道后直接预览或导出，无需先去发现页逐个打开。

若需要最新内容，点击“更新频道并预览”；展开“本次内容检查”查看不足原因。自定义频道没有已生成期刊时，先在桌面正常生成，或调整回看天数。普通导出复用缓存，不保证每次联网刷新。

已经下载的 HTML 是静态快照，必须重新生成才能使用修复后的内容。现有邮件配置没有被修改，没有发送测试邮件；08:00 是生成开始时间，取数与等待会让邮件稍后送达。

## 更值得继续做的优化

优先补充账户与来源隔离的 HTML 专用持久缓存，让仅由导出流程取得的内容在桌面重启后也能离线回用，并提供保留期限与清理。当前已有桌面浏览库可恢复，但本轮新增的短期准备缓存仅在内存中。

其次将“补齐缺失／优先缓存／强制更新”做成明确的内容来源策略，并在频道高级设置显示来源条件及缓存年龄；目前通过普通生成与“更新频道并预览”区分这两种行为。

随后增加可选的“有内容但没有已有摘要”统计，帮助用户在桌面决定是否人工分析；不能自动调用 AI 来填充摘要，也不能把未分析项目误报为失败。

这些是后续建议，本轮没有擅自增加新的设置层级、自动计费任务或邮件重试策略。
