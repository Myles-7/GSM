# 仓库治理

个人仓库 Myles-7/GSM，上游 AmintaCCCP/GithubStarsManager。`main` 是唯一长期主分支，也是默认分支。开发时可以短期使用 `codex/*`，通过检查并合入后删除；不建立备份分支、阶段恢复标签或源码副本。正常提交历史保留，以便追查问题。应用版本保持 0.8.4，选择性集成不冒称完整升级。

合入前运行 `npm run check`、`npm run test:run`、服务端测试与类型检查、`npm run build:all`。CI 前端 Node 24，服务端原生依赖 Node 22。未执行的真实供应商、安装、手机和部署验证须明确列为限制。

源码、测试和维护文档按用途拆分提交，推送前审查 diff 与敏感信息，使用普通 push。`main` 禁止强制推送和删除，合入要求 Quality gates 与 Server quality gates 成功；GitHub 自动删除已合并的临时分支。不要改写已经共享的提交来美化历史。

个人仓库的普通推送（包括 `main`）不发布安装包或容器。容器发布仅允许在 `main` 上显式运行对应 workflow_dispatch；上游仓库保留其发布规则。桌面工作流保留多平台打包验证，个人仓库不会自动发布上游安装包。

不提交数据库、密钥、本机部署、依赖、生成物、截图和报告。历史方案与源码恢复点通过 Git 查找，不在源码目录复制 backup/old/copy。产品数据备份和迁移功能保留；Git 无法恢复未备份的运行资料。

生产模块从 `src/main.tsx` 的导入图检查可达性：`npm run check:unused` 会跟踪静态导入、re-export、动态 import、require 和 Worker URL。测试、fixture、声明及测试运行配置单独识别，不算应用入口。新加独立运行入口时应同步更新检查器入口并测试，不能为了通过检查添加虚假的副作用 import。

项目目录保留源码、当前构建、必要依赖和实际运行资料。`output/` 用于当前诊断结果，过期测试临时目录、旧候选构建与重复部署包可删除；先核实服务和启动脚本使用的路径，不能按目录大小推断无用。日常固定白名单清理使用 `npm run clean:workspace -- --apply`。

Windows 工作树可能通过 junction 共用当前项目的依赖。删除工作树前必须扫描其子目录链接，先以非递归操作移除链接本身，再删除旧目录；不能直接对含共享 junction 的工作树执行强制递归删除。目录没有源码差异，不代表它的依赖可以递归删除。

重新编译、提交和 push 不代表正在运行的 Windows 后端或另一台设备已经升级。
