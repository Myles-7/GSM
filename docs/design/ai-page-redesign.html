01

现状与问题诊断

先理解现状，再谈设计。当前 AI 页面功能强大但界面已出现「密度过载」：单个 1300 行组件承载了会话管理、对话、研究状态、提案审查、需求编辑五类异质内容。

问题现状描述影响
顶栏认知过载高度 44px 的 header 内并排 8+ 元素：折叠钮、图标、标题、Chat/Overview 选项卡、项目名、导出、仓库入口高频功能互相挤压，扫视成本高
对话流混杂消息、需求编辑器、操作提案、组织面板按纵向堆叠在同一滚动流中打断阅读节奏，对话与「行动」边界模糊
输入区参数常驻范围 / 模型 / 深度 3 个 Select + 管理复选框常驻输入区视觉噪音大；移动端需折叠为胶囊二次点击
会话列表信息密度低会话仅显示标题，无摘要与上下文元信息，分组仅靠项目段落历史找回成本高，长列表难以定位
状态反馈弱任务运行仅一行 12px 边框状态条；提案到达依赖脉冲徽标 + 浮动胶囊长时间研究任务缺少可感知的进度
移动端补丁式键盘弹起 hack、移动胶囊按钮等补丁逻辑内嵌于桌面布局三端体验割裂，代码分支多

现状布局 vs 新布局

现状：两栏 + 聊天流承载一切 AS-IS
历史侧栏 220px标题列表，无分组无摘要
密集顶栏（8+ 元素）标题/选项卡/操作全在一行
聊天滚动流（混杂区）消息 + 需求编辑器 + 提案 + 组织面板纵向堆叠；底部 Composer 常驻 3 Select
新方案：三栏工作台 + 纯净舞台 TO-BE
会话侧栏 258px新对话置顶 · 搜索 · 智能分组 · 摘要 + 状态
轻量顶栏标题 + 分段控件 + 收纳操作
对话舞台（纯净）任务进度条 · 消息 + 证据折叠 · Composer（参数收纳）
工作台 Dock 344px候选仓库 · 提案审查 · 需求编辑，可折叠
核心洞察：本项目 AI 页面与通用聊天产品的最大差异，在于「对话之外还有行动」——候选仓库、字段变更提案、需求驱动搜索。新设计的胜负手不是把聊天做漂亮，而是给行动一个专门的家（右侧 Dock），让对话流回归纯粹。
02

设计原则与习惯映射

六条原则指导所有界面决策；每一条都可追溯到「用户习惯」——要么延续已被主流 AI 产品教育的模式，要么延续项目自身的视觉基因。

CONVERSATION FIRST

对话即舞台

中央区域只做一件事：高质量的问与答。需求编辑、提案审查等非对话内容一律移出滚动流，进入专用面板。

PROGRESSIVE DISCLOSURE

渐进披露

高频操作一屏可达；范围 / 模型 / 深度等低频参数收进一个「参数」入口，需要时展开，不需要时不占视觉空间。

FAMILIARITY

习惯延续

沿用 ChatGPT / Claude 教育出的「侧栏 + 舞台 + Composer」心智；沿用项目已有 shadcn 视觉语言与快捷键习惯，零学习成本迁移。

ACTION VISIBILITY

行动可见

提案是本产品独有价值。给提案一等公民待遇：专门审查卡片、清晰 diff、批量勾选、执行进度与结果一目了然。

TRUST & EVIDENCE

信任与证据

答案必须可溯源：证据默认折叠为计数徽标，展开显示仓库 / 文件 / 行号 / 新鲜度，本地与远程来源视觉区分。

RESPONSIVE BY DESIGN

全端一致

桌面三栏 → 平板两栏 + 抽屉 → 手机单栏 + 底部工作台，一套信息架构三端适配，不再是补丁式兼容。

⌘K / Ctrl K 唤起搜索（IDE、Notion）侧栏搜索框带 ⌘K 快捷键徽标，全局可唤起会话搜索

设计规范

所有视觉值映射到项目既有 Theme Token 体系（src/lib/themePresets.ts + CSS 变量），不新增颜色字面量；主题预设、深浅色、圆角与动效偏好自动生效。

色彩 Token

Primary--primary主操作 / 激活态
Primary Soft--primary/10气泡 / 高亮底
Surface--background卡片 / 面板
Subtle--muted工具条 / 分组头
Success--success已验证 / 执行成功
Warning--warning验证中 / 待确认
Danger--destructive取消星标 / 错误
深浅色双模式验证：切换原型顶部「深色」可检查全部组件在两套主题下的表现——本方案未使用任何硬编码颜色，全部通过语义 token 引用，因此主题预设（15 套）与用户自定义强调色（8 色）均可直接生效。

06

实施路线

三个渐进阶段，每阶段独立可交付、可回滚。全程不修改 useAIWorkbench Hook API、persistence、autoSync——纯 View 层重组，符合项目「新 Feature 优先新增文件」的基线策略。

P1 · 约 1–2 天

阶段一：骨架重组

把 1300 行单文件拆为职责单一的组件，布局落位，不改任何业务逻辑。

  1. 新建 WorkbenchShell（顶栏 + 三栏骨架 + 折叠状态持久化到 preference）
  2. 抽出 SessionSidebar（分组列表 / 搜索 / 模式切换 / 底部工具）
  3. 抽出 ChatStage（消息流 + 任务条）与 Composer（上下文 chips + 参数 Popover）
  4. 现有 AIWorkbench.tsx 保留为组合层，只做组件编排
验收 · check:boundaries + lint + typecheck 通过；AIWorkbench.test.tsx 现有断言（含 data-testid）全部通过
P2 · 约 1–2 天

阶段二：工作台 Dock 与提案

行动内容迁移出聊天流，提案审查体验升级。

  1. 新建 WorkbenchDock（候选 / 提案 / 需求三 Tab，可折叠 ⌘/）
  2. OperationPreview → ProposalReviewCard：diff 审查 + 批量勾选 + 执行进度
  3. RequirementsEditor 移入 Dock 需求 Tab；聊天流移除对应区块
  4. 新建 EvidenceList 折叠组件，替换消息内常展开的引用区
  5. 「对话 / 工作台」视图分段控件替代现有 Chat/Overview 选项卡
验收 · i18n check（9 语言 key 补齐）通过；提案执行 / 撤销路径手动回归
P3 · 约 1 天

阶段三：移动端与打磨

系统性响应式 + 微动效，移除键盘 hack 补丁。

  1. 移动端：侧栏抽屉 + Dock 底部抽屉 + FAB + Composer 粘底（替换 isKeyboardOpen 补丁为 visualViewport 方案）
