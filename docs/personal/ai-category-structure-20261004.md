## 使用方式

仓库工具栏的“AI 整理”分为“仓库归属”和“分类结构”。

- 分类结构：直接新建一级类别，或让 AI 提出新建、改名、合并草案；检查影响后明确确认。创建空类别不需要 AI 模型。
- 改名保留分类 ID、仓库归属、锁定和 GitHub Lists 关联。
- 合并包含来源和目标下的全部仓库；AI 重新设计二级归属，优先复用已有分组。资料不足可补充 README、手动指定或接受原分组迁入映射。
- 完整合并前必须解决所有目标、逐项授权锁定的跨一级移动并选中全部变更；内置来源移空后隐藏，自建来源删除。
- “仅迁移选中的归属”产生独立归属记录，保留来源结构；原完整合并草案成为历史版本，继续完整合并需要新预览。
- 仓库归属默认补齐缺失整理；重新整理允许跨一级移动。全部仓库与当前筛选结果明确区分，目标按一级、二级联动选择，支持分组、平铺和批量调整。
- “保持原位置”保留人工安排；“只补二级”约束下一轮一级归属；“重新安排”允许下一轮重新评估。模式和约束由执行器校验。
- 续聊累积原要求，保留人工修改的结构及归属；未人工修改的仓库重新评估。超过要求长度上限时提示精简，不静默丢弃原条件。

## 数据和恢复

新草案使用版本 2，旧版本 1 不推断结构操作。沿用聊天库和统一 Store 事务，不提高主 Store 持久化版本、不迁移数据库表。

结构事务记录分类定义、关键词、归属、顺序、隐藏状态和本地 Lists 映射。目标 Lists 关联保留，已删除来源的本地映射解除；不请求远端 Lists 改名、合并或删除。

内置合并来源的 `mergedInto` 保存在已有 `defaultCategoryOverrides` 中，经本地持久化、账号空间、后端同步和备份传递；自动分类不推荐这些退役来源。旧仓库归属不因该字段自行改变。

确认绑定草案版本、账号及完整成员集合；新增范围外成员或修改分类/归属会阻止整个结构操作。恢复采取保守检查：后续分类结构、顺序或相关仓库归属变化时暂停，不覆盖修改。

执行前写入日志，重启只核实状态，不重放写入。JSON 导入的结构草案保持未选中、只读。同步失败与本地成功分别展示，同步重试不重放结构操作。
