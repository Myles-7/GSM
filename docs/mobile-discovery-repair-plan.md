# 手机发现修复方案（2026-09-30）

本轮根据真机截图修复可用性，保留已经确认的手机功能范围。

## 已确认的问题

- 实际 Windows 服务仍运行 `0.8.4-20260930061742122`。私人 HTTPS 能访问、鉴权有效、基础发现可用，但能力响应没有 `stablePopular` / `publicReleases`，手机正确拒绝调用新版频道。必须部署新后端，不能仅修改能力提示。
- 手机的未确认任务只有成功时才清除。明确拒绝也保留提交记录，后续不同任务被全局阻挡；现有恢复入口再次收到拒绝时仍无法解除。
- 服务任务记录没有成功接收的自定义频道任务。手机本机提交记录不可直接读取，因此不把推测的首次失败原因描述为已确认。

## 实施

1. 增加按客户端请求 ID 查询回执的鉴权接口；不创建任务、不调用模型。
2. 服务只在确认未落库、且为已知提交校验拒绝时返回 `accepted:false`。网络错误、内部错误、鉴权失败和已有请求冲突保持不确定状态。
3. 统一手机提交和恢复。明确拒绝解除当前记录并给出可读错误；断网或响应丢失保留原请求，显式恢复重用相同 ID，避免重复计费。查询不存在不作为丢弃请求的依据。
4. 自定义频道在原页面显示未确认任务及恢复按钮；已接收的任务返回正确频道或会话。日期按本地年月日构造，不依赖系统区域格式。
5. 备份正在运行的 SQLite，构建和升级真实服务；检查能力、热门发布、稳定热门列表、趋势、主题、搜索及期刊链路。未知来源错误保留旧内容。
6. 回归任务幂等性、失败恢复、账户隔离与频道切换；构建同 ID、同证书 APK，并记录实际验证范围。

最终实现补充：明确拒绝的请求 ID 在服务端事务内持久记账，迟到的相同请求不能因配置修复而变成已接受；缓存任务只用于定位，清除未确认提交必须有当前账户的真实后端回执。前端完整 2303 项、后端 280 项测试通过。实际服务升级因 Windows UAC 取消尚未完成；最终产物及待验收项见 `mobile-discovery-repair-delivery.md`。

## 发布验收

真实 HTTPS 接口验证与浏览器回归分别记录。真机覆盖安装、移动数据和应用本机旧提交的恢复需要独立确认，不能以模拟数据代替。保留工作区、草稿、业务数据、待上传队列和凭据。
