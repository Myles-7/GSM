# GSM 每日 HTML 阅读与回传方案

首次实现日期：2026-09-30；更新日期：2026-10-03。桌面设置、HTML生成、邮件调度和回传合并已实现，本轮新增桌面主题还原、手机详情／频道导航及v2继续阅读位置。最终测试和构建结果见 [本轮改造记录](html-reading-redesign-20261003.md)；实际邮箱发件与手机打开仍未验收，当前运行程序升级需另行核对。

## 最终决策

停止 Android APK 开发，从当前源码和构建流程移除移动应用。电脑运行 GSM，通过桌面设置 → 每日 HTML 决定内容，默认北京时间 08:00 生成并通过 Gmail 发送附件。手机只阅读仓库和发现，使用已有 AI 摘要与分析；日报流程不新增自动 AI 请求。

手机可修改已读、感兴趣／忽略、阅读笔记、收藏候选。导出修改文本或 JSON，在桌面先预览再确认合并。分类仍在电脑处理，导入候选不执行 GitHub Star。

## 桌面设置

| 分组 | 可设置内容 |
|---|---|
| 页面与仓库范围 | 标题、仓库／发现开关、分类、仓库数量、默认排序、只看未读、隐藏忽略 |
| 发现频道与历史 | 内置／自定义频道选择、内置每频道数量、自定义每期独立数量、已有期刊回看天数 |
| 内容字段 | AI 摘要、原始描述、标签、分类、语言、Star、更新时间、笔记、推荐理由、真实版本说明、来源及分析时间 |
| 分析栏目 | 问题、功能、场景、架构、快速开始、部署、成本、维护，可独立开关 |
| 阅读样式 | 摘要字符上限与4／6行展示、默认页面、继承桌面主题及强调色、明暗模式、字号、密度、附件体积上限 |
| 手机操作 | 已读、兴趣、笔记、收藏候选，各自可禁用 |
| 邮件与调度 | Gmail 本机加密授权、收件地址、连接测试、时间、发送前更新、等待已有更新、立即发送、执行记录 |
| 回传导入 | 粘贴／选文件、差异与继续阅读位置预览、冲突选择、去重、阅读记录及候选确认；接收旧v1和新v2 |

关闭的内容从文件载荷排除。缺失分析栏目不占位，不显示原始 JSON。预览与导出使用当前表单；每日任务使用已保存设置。笔记默认不随邮件发送。

## 更新与发送

Electron 主进程触发当天任务，桌面渲染进程读取实际 Store、发现 IndexedDB 与已缓存分析。内置频道每项最多等待 30 秒，总共最多 90 秒；失败保留当前会话缓存和真实更新时间。可等待正在执行的自定义发现任务最多 60 秒，不启动任何新 AI 任务。生成有主进程截止时间，超时记录失败。

08:00 是开始更新时间，不能保证收件箱恰好在 08:00 收到。GSM 必须运行，电脑不能持续休眠；恢复后只检查当天任务。每天每账户最多一次自动尝试，失败／中断留记录供手动处理。SMTP 回执不确定时不会自动重发，先查收件箱。

## HTML 与回传可靠性

单文件内置内容、样式和必要脚本，不请求服务器或模型。来源通过外链打开；不内置完整 README、图片、密钥或桌面本地目录。共享桌面主题、图标及详情分区规则，手机使用固定双入口与按频道浏览；列表每批40项、最多同时挂载120张卡片。脚本受限时只能显示首批列表，频道、详情及回传需要下载后在支持脚本的浏览器打开。

分析来自桌面同账户、项目数字ID及语言的共享资产，保持模型切换后的已有结果与人工删除屏障。关闭的字段从载荷裁剪；自定义历史按期保留日期、完成状态及推荐理由，不合并为一个去重列表。最终文件超过配置体积上限时明确失败。

尝试按原文件保存手机修改，但本地 HTML 的浏览器存储并不可靠。关闭前导出修改；复制失败可手动选择文本或下载 JSON。原文件可以载入自己的回传包，不能把旧包直接套入新日期快照。

每项操作携带唯一ID、账户、原快照、项目数字ID、字段基础值和新值。桌面核对真实导出记录与允许操作，同字段冲突保留双方待选择；应用时再次检查预览后的变化。新v2回传附带活动页面及频道／期刊项目锚点，可以仅导出位置；旧v1仍可导入原业务修改。业务修改、位置与去重回执同一IndexedDB事务落盘，旧快照的迟到位置不会覆盖新位置，不覆盖分类或AI分析。收藏候选需另行确认，并核对GitHub项目ID，才执行Star。

这些是手动回传，不是实时同步。尚未导回电脑的阅读状态和位置不会出现在次日文件中。新文件根据已回传的稳定项目ID尽量继续定位，项目、期刊或频道缺失时退回附近项目或可用页面并提示；当天顺序跟随桌面快照。

本机`gsm-html-reading`升级为数据库版本2，旧设置补默认并保留原选择，首次迁移前资料在`migration-backups`中按账户保存一次；备份和升级资料同事务提交，失败时保持原数据。备份仍位于同一桌面资料目录，不是异盘备份或自动回滚界面。
