## 分析与实施结果

| 发现的问题 | 方案与已完成改动 |
| --- | --- |
| 品牌、同步行、页面标题、频道横幅重复，占据首屏 | 顶部统一为当前页面标题，正常同步压缩为状态入口；发现使用当前频道行和常用频道栏。390px 测试截图中，首张发现卡片起点从约 410px 提前到 242px |
| 仓库默认概览偏重人工编辑资料，已有分析仍需查找 | 概览优先展示项目摘要、解决的问题、核心功能和场景；保留完整 AI 分析与 README，隐藏未知／空字段和空工具栏。旧格式结构化功能描述也可阅读 |
| 阅读、编辑、分享和重新分析混排 | 仓库主要操作为“问问 AI”和“AI 分析”；编辑资料、GitHub、分享、重新分析进入仓库操作。发现卡片显示“了解项目”“收藏”，点击了解先进入详情 |
| 分析提交后进度和结果分散 | 仓库／发现详情原位显示任务状态；完成结果在同步投影更新前也可读取。已有有效分析直接打开；只有元数据或未知的对象不阻止首次分析 |
| 刷发现反复点击分页、筛选含无效选项 | 近底部受控追加，保持稳定 ID 去重和热门批次；出错后停止自动重试，两次空批次后暂停，保留手动续看。只显示对应频道实际支持的筛选，编辑留在草稿，应用后请求 |
| 修改发现搜索词可能被分页意外提交 | 新关键词必须明确点击搜索。未提交期间保留旧结果并显示提示，暂停旧分页的自动加载 |
| 长列表、README 和周刊返回容易失去位置 | 切换前捕获位置；详情返回和页签固定在顶部，长 README 等待内容就绪后恢复。周刊／期刊打开置顶，返回恢复来源列表，期刊内部项目返回也保留阅读位置 |
| AI 首屏要求理解工作台术语 | 默认直接提问，按通用／仓库／候选场景提供示例；项目、需求、候选、比较、提案仍完整保留在明确标注的研究工作台。模型和工作台合并到控制行，历史与新对话有文字入口 |
| 普通聊天不会搜索，原中文研究请求直接当 GitHub 词 | 新增明确的 AI 查找模式：用户确认可编辑的 GitHub 搜索词 → 最多 4 个候选 → 后台根据原问题读取总结。中文知识库、自托管、自动化、开发工具快捷词只填写草稿，不自动产生付费请求。粘贴 GitHub 链接直接作为取证仓库 |
| 草稿、重试与任务回到错误上下文 | 每个会话分别保存问题、查找模式和搜索词；新对话保留旧草稿。无结果后改词复用原问题；响应丢失后复用同一候选、消息和请求。找回任务按请求 ID 确认收据，任务上下文只发送给目标页面 |
| 流式回答与历史阅读互相打断 | 正文增量通知聊天层，主动跟随时滚动；阅读历史时保持位置并显示新回答入口。隐藏页面不自动跟随 |

## 部署与验收边界

本轮未改动电脑后端、密钥和真实资料，也未再次尝试此前取消的 UAC 升级。电脑现有发现基础接口可继续使用；热门 Release 和稳定热门新协议仍需运行根目录 `GSM-升级电脑后端.cmd` 完成已准备的后端升级，并在手机重新验证能力。不能把 APK 构建成功描述为后端已部署。

ADB 当前没有连接设备。真机覆盖安装、手机移动数据、实际软键盘、系统返回键、锁屏和重入仍未验收。浏览器模拟布局、单元测试和相同签名校验不能替代这些项目。

发现列表会保留已加载项目以保证续看顺序；本轮没有新增完整列表虚拟化，因此不将仓库分页测试等同于任意长发现列表的真机性能结论。
