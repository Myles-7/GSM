# P0.2.1 桌面启动维护补丁

日期：2026-10-02，Asia/Shanghai。源码提交：`8754dce39add1fb2fd4522e204f28a3877b16ebb`。
个人交付为 P0.2.1，应用 package 与完整上游基线仍为 0.8.4；P0.2.0 选择性迁移来源、排除项和旧标签不变。本次仅本地交付，未推送远端、发布安装包或更新服务。

## 原因与修复

- 实机有两个不同快捷方式。桌面 `GitHub Stars Manager.lnk` 原先经 WScript 启动 `launch-desktop.mjs`，进入 Vite/5174 开发模式；文件夹里的 `GSM-桌面端.lnk` 原先直接启动控制台 Node。此前“常用入口已统一”的记录不能代表这个遗留桌面入口。
- 原日志证实重复启动争抢 5174，Vite 退出后触发多层失败提示。现在两者均使用 `start-desktop.vbs -> start-home-desktop.cjs -> electron/main.js -> dist/index.html`，隐藏启动控制台，不等待或启动 Vite、临时后端。
- 启动前校验构建文件，启动器保留本地日志和非零退出提示；后端服务独立运行，不把网络超时作为应用无法启动。
- 修复 EPIPE 输出断管异常，仅容忍 EPIPE，其他异常仍报告。修复失去单实例锁的第二进程继续初始化窗口、HTML Reading 和 Chromium 缓存的问题；立即以 0 退出，原实例正常唤回。
- 禁止自动上游更新请求与横幅，清理旧通知。设置保留“查看上游更新”，查询结果明确为上游参考，不宣称个人版已最新或可直接覆盖。手动请求包含响应体在内限时 10 秒，卸载取消，失败可重试。
- 仅增加无敏感内容的 Performance marks，记录恢复、首帧与 Home 初始化；没有改写 Home 权威性、操作确认顺序、仓库渲染或同步算法。

## 本机测量

测试使用真实生产 main、原 Windows userData 与真实账号；测试护栏阻止付费 AI 和外部写入，允许正常 Home 同步。下列时间来自单次样本，不是多次统计或性能保证；未清空系统/Vite 缓存，不是新电脑首次安装测试。

| 场景 | 首屏可操作 | 结果 |
| --- | --- | --- |
| 原开发模式，Vite 已正常响应 | 3,745 ms | 250 个资源；不包含端口争用失败的等待 |
| 原生产模式，设置视图 | 514 ms | 24 个资源，说明瓶颈主要在旧入口而非新迁移业务 |
| 修复后生产模式，62 仓库视图 | 641 ms | Store 恢复约 35 ms；Home 约 2.36 s 后台就绪 |
| 本应用请求中模拟后端不可用 | 637 ms | 本地仓库可用，未停止共享 Windows 服务 |
| Home 响应额外延迟 3 秒 | 636 ms | Home 约 5.57 s 就绪，首屏不等待远端 |
| 直接冷启真实桌面 `.lnk` | 窗口出现 1,024 ms | 包含 WScript/Node 包装；这是窗口出现时间，不冒充可操作时间 |

真实 `.lnk` 重复点击及正常关闭到托盘后唤回约 1.27 s，包含测试驱动 PowerShell 的额外开销；仅一个主实例，无第二进程窗口、缓存争用或加载失败。开发模式与生产模式的入口、视图、资源集不同，不能将资源数量或耗时差异当作同一渲染组件的优化比例。

62 仓库首绘仍有约 240 ms 长任务；之后采样帧最大间隔约 4.7 ms，没有复现持续卡顿。因此不顺带重写列表或虚构“零长任务”。更大数据量、不同硬件与长期运行仍可能有其他瓶颈。

## 使用与维护

仍只使用 `D:\桌面\GSM` 及已有快捷方式；修复后应用已通过真正桌面快捷方式打开。开发入口仍可用于工程调试，但不再作为日常入口。
快捷方式需重建时由 `scripts/install-desktop-shortcuts.ps1` 显式更新，普通启动不重新注册服务或修改快捷方式。诊断仅看 `logs/desktop-*.log`，不需用户管理恢复工作区。
