# 每日 HTML 桌面风格与手机阅读改造

日期：2026-10-03。本文件记录本轮实际实现、验证结果和使用边界。前端全量回归、桌面回归、生产构建及隔离浏览器验证已通过；这不表示用户当前运行的桌面程序已重新加载新构建。没有实际发送邮件，也没有完成安卓真机或 Gmail 附件验收。

## 本轮变化

HTML 改为桌面主题下的项目阅读界面：底部固定“仓库／发现”，顶部提供搜索、明暗切换、快照信息和导出。仓库与发现采用相同的紧凑卡片，点击卡片进入本地全屏详情，外部 GitHub 链接位于详情顶部。

| 区域 | 当前行为 |
|---|---|
| 主题 | 生成时捕获桌面预设、强调色、圆角和减少动画偏好；浅深色分别保留；字体采用预设名称及系统回退，不下载字体或头像 |
| 卡片 | 首字母头像、项目与所属者、默认最多6行用途摘要、最多3个标签／分类、语言、Star与已读；摘要优先使用已有 AI 内容，无摘要时使用允许导出的原始描述 |
| 详情 | 按“概览／使用／维护”组织已有分析；保留列表、步骤和命令代码块；命令支持复制；没有内容的栏目和分区不显示 |
| 依据与上下文 | 来源链接与分析时间默认折叠；推荐理由和真实 Release 在详情展示，不挤占卡片 |
| 仓库 | 文件内搜索、分类抽屉、可移除条件；返回列表恢复浏览位置 |
| 发现 | 一次查看一个频道，横滑快捷栏与完整频道抽屉；自定义频道默认最新一期，可选择已导出的历史期刊 |
| 修改 | 卡片直接切换感兴趣／收藏候选；详情提供已读、忽略、候选和笔记；开启已读权限时，打开详情自动标记已读 |
| 继续阅读 | 同一文件各页面、频道及期刊分别保存搜索、位置和详情分区；导出位置到桌面后，下次生成按项目稳定 ID 尽量定位 |
| 性能 | 首批40项，继续浏览时分批加载，最多同时挂载120张卡片；项目数据在文件载荷中保存一份，频道与期刊保存项目引用 |

手机小于600px采用单列，600px以上采用双列，宽屏限制内容宽度。保留安全区域、44px点击目标、长代码横向滚动和浏览器历史返回处理。实际手机键盘、返回键及附件打开仍需真机验收。

## 桌面设置与使用顺序

1. 使用包含本轮改造的桌面版本，打开 **设置 → 每日 HTML**。替换桌面构建后需从托盘退出再启动；仅关闭窗口可能仍在运行。
2. 在内容分区选择仓库范围、发现频道、期刊历史、导出字段、分析栏目和手机操作。
3. 在样式分区选择摘要4／6行、14／16／18／20px字号、紧凑／标准密度、初始页面和明暗模式。主题预设与强调色始终来自生成时的桌面设置。
4. 点击 **预览 HTML**，使用360、390、430、768、1024px视口与浅深色切换检查实际生成文件。预览中显示各频道／各期期刊条目数量和实际文件体积；预览标记与桌面阅读记录隔离。
5. 点击 **导出 HTML** 保存文件。若要用于每天自动发送，另点 **保存设置**；预览和手动导出使用当前表单，定时邮件使用已保存配置。
6. 邮件配置、授权和发送沿用现有 Gmail 流程。测试连接不发送邮件；实际发送仅在用户主动操作或已启用的每日任务中进行。本轮没有代填授权码或测试真实发件。

“摘要字符上限”决定文件实际保留多少摘要；“展示行数”只决定卡片高度。进入详情可以阅读本次导出的完整摘要，但不会读取被字符上限裁掉的文字，也不会在线补全内容。

关闭字段会从数据载荷排除，包括分类名称和分类 ID；关闭分析栏目不会把其内容藏在 JSON 中。个人项目说明、模型密钥、邮箱授权、GitHub Token、电脑路径等运行配置不进入快照。阅读笔记默认不导出，只有开启对应字段才带入已有笔记。

## 数据来源、数量与失败提示

仓库和发现使用与桌面相同的账户级分析资产：按 GitHub 数字账户、项目数字 ID及语言选择已有成功结果，不再要求恰好匹配当前模型。切换模型或项目更新时间变化不会让已保存分析消失；当前语言优先，没有时按桌面规则使用已有其他语言结果。

旧仓库和账户内的有效缓存可以迁移为分析资产。人工删除标记与账户级删除屏障禁止旧缓存恢复已删除分析；未知来源或不匹配的旧发现列表摘要不会被直接带入。整个日报过程不启动 AI 调用。

- 收藏仓库使用仓库总数量上限；内置发现使用每频道数量上限。
- 自定义频道使用**每期期刊**数量上限，而非把多期期刊合并后共用一个限额。保留期刊稳定标识、日期、生成时间和完成状态；同一项目在各期的推荐理由可以不同。
- 期刊回看天数决定进入文件的历史范围；超过每期上限会标注该期的匹配数和导出数。
- 文件上限保持1–15 MB。最终文件超过配置上限时生成失败，并明确要求减少数量、历史天数或分析栏目，不静默丢弃项目。
- 内置频道无缓存、因当前条件筛选后为空、缓存距今超过24小时分别提示。旧缓存仍可以阅读，其更新时间不会伪装为本次生成时间。
- 期刊未完成时展示已保存项目并说明；范围内没有期刊时说明缺少已有内容，不触发新的生成。
- “热门发布”使用桌面已核验的真实 Release 结果，优先保留频道内的发布标签、实际发布日期及已有标题或说明。缺少有效发布资料的旧缓存明确提示需要刷新，不把仓库推送时间当成发布；导出本身不新增联网或 AI 请求。

Gmail调度和等待规则保持原实现：默认北京时间08:00开始处理，GSM需要运行、电脑需要醒着；内置刷新每项最多30秒、总共90秒，可额外等待正在执行的自定义更新最多60秒。这不是保证08:00送达，不会启动新的自定义 AI 更新。发送失败或回执不确定时先检查邮件状态和收件箱，不盲目重发。

## 手机回传与继续阅读

从 Gmail 下载附件后，使用支持本地 HTML 脚本的浏览器打开。邮箱内置预览或部分文件查看器可能只显示首批内容，不能使用详情、频道、标记和导出；应下载后再打开。单文件不依赖原手机后端、Tailscale或实时网络同步，只有主动打开来源外链需要网络。

阅读后点顶部 **导出**，复制文本到桌面 **每日 HTML → 导入手机阅读记录**，或下载并选择 JSON。复制失败时可以手动全选文本；关闭文件前确认修改和位置已导出。本地浏览器保存失败会提示，导出仍可保存当前会话的修改和位置。

桌面先预览四类业务修改及“继续阅读位置”。有笔记或兴趣冲突时逐项选择手机／电脑版本，确认后再导入。收藏候选导入不执行 Star，仍需要桌面单独确认并核对项目数字 ID。

下一份文件使用已导回桌面的记录：优先定位同频道、同期期刊的同一项目；该项目不在新文件时寻找原列表附近的仍可用项目并提示。期刊不再包含时返回该频道最新一期，频道不再包含时返回可用页面。每天内容顺序仍跟随当天桌面快照，未回传的手机位置不能自动跨文件延续。

### 版本兼容

| 版本对象 | 当前格式与兼容 |
|---|---|
| 设置 | 保持 `version: 1`，读取旧设置时补齐新增默认值，保留既有内容选择、字号、邮件和操作配置 |
| 阅读快照 | 新生成文件为v2，使用唯一项目表、频道／期刊引用、主题和位置；旧HTML文件仍可按其内置脚本自行运行 |
| 回传 | 新文件导出 `gsm-reading-changes` v2；桌面同时接收严格v1与v2，v1仍可导入原有修改，v2额外支持位置及活动页面 |
| 本机IndexedDB | `gsm-html-reading`升级为数据库版本2，按账户保存旧资料迁移前副本和新位置记录 |

每份回传仍须匹配原账户、原导出快照、允许字段和基础值，不能把旧文件的回传包直接套入另一份日报。v2允许没有业务修改、只有阅读位置；重复操作和位置会去重。旧快照迟到的位置不会覆盖较新位置，但其业务修改仍独立进入原有冲突处理。

业务修改、位置与去重回执在同一事务提交。导入预览后桌面记录发生变化会要求重新预览，不静默覆盖。

## 迁移、资料保护与验收状态

首次读取旧账户资料时，迁移前副本与第一次v2账户写入在同一 IndexedDB 事务提交；失败回滚，不改坏旧资料。备份位于 `gsm-html-reading` 的 `migration-backups`对象仓库，以 `<账户ID>:before-v2`为键，只保存一次，原有设置、记录、快照基础值和去重记录均保留。

这份副本仍在原桌面浏览器资料目录中，不能替代异盘备份；当前没有新增通用备份导出或一键回滚界面。不要删除Electron资料目录或手工使用旧程序改写新位置结构。邮箱加密授权及邮件状态沿用原位置，本轮不清除或轮换授权。
